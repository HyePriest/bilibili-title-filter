# B站首页过滤 0.7.11

一个只处理哔哩哔哩网页首页的 Chromium 扩展。Chrome 与 Edge 使用同一份安装包。

## 功能

- 弹窗右上角提供总开关：关闭后恢复当前首页视频、暂停过滤和自动补加载，保留规则与历史；重新开启后立即重新过滤。开关不写入 Chrome / Edge 共用的规则文件。
- 当前首页和最近100条记录按“质量问题”“特殊样式”分组；关键词（包括用户填写的“纪录片”）与质量评分归入质量问题，特殊类型规则归入特殊样式。同时命中两类时归入质量问题并保留全部原因；仅命中屏蔽名单的记录在“其他屏蔽”中展示。
- 按标题关键词过滤视频，默认包含“大型纪录片”。
- 按 UP 名称关键词过滤视频，默认包含“纪录片”和“记录片”。
- 在同一个屏蔽名单中管理 UP 完整名称和 UID；UID 在 UP 改名后仍然有效。
- 按视频分区和标签关键词过滤。
- 按特殊类型徽标和专用链接过滤，默认屏蔽课堂、直播、综艺、番剧、国创、电影、电视剧和纪录片。
- 使用投币、收藏、点赞、同UP重复和近期重复推荐计算质量分。
- 提供宽松、标准、严格三档；低于当前阈值的视频直接隐藏。
- 读取并同步当前 B 站账号的官方拉黑名单。
- 在首页视频卡片上一次完成“内容不感兴趣”、官方拉黑 UP 和加入插件屏蔽名单。
- 屏蔽名单按最近新增或再次添加排序，并在 Chrome、Edge 的共享状态中保留该顺序。
- 显示当前首页和最近 100 条屏蔽记录，包括封面、标题、UP、UID和命中原因。
- 从屏蔽记录中直接添加 UP，或者让某条视频在本次页面临时显示。
- 隐藏推荐网格的完整布局项，使剩余视频自动补位。
- 过滤后若加载标记已接近视野底部，自动通知 B站继续加载下一批推荐；保留滚动位置，等待正在进行的加载，无进展时限制重试。
- 加载标记随第一个待加载空位排列，避免过滤后行数错位、空位可见但加载标记仍在下一行而停住。
- 保留 B 站原生加载占位，不再隐藏尚未加载的视频；卡片复用和推荐区替换后自动重新检查，单张卡片异常不会中断其余视频的更新。
- 关键词使用标签式输入，支持回车、逗号和多行粘贴。
- 通过本机共享状态文件，让 Chrome 与 Edge 对规则和屏蔽名单取并集。

## Chrome 安装或更新

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 首次安装：点击“加载已解压的扩展程序”，选择 `bilibili-title-filter` 文件夹。
4. 更新旧版：在扩展卡片上点击“重新加载”。
5. 刷新已经打开的 B 站首页。

## Edge 安装或更新

把上述地址换成 `edge://extensions/`，其余步骤相同。

## 使用说明

点击浏览器工具栏中的扩展图标，弹窗分为三页：

- “过滤规则”：管理标题、UP名称、分区、标签关键词和质量过滤强度。
- “屏蔽记录”：检查实际匹配的视频、查看原因、打开视频或屏蔽对应 UP。
- “屏蔽名单”：在一个输入框中添加完整名称、UID或个人空间链接，并同步 B 站官方拉黑名单。

关键词输入后按回车即可保存。一次粘贴多行文本或使用逗号分隔时，会自动拆分为多个标签。

将鼠标移到首页视频卡片上，UP 名称旁会出现“拉黑”按钮。点击并确认后，扩展会先触发同一张卡片上的 B 站原生“内容不感兴趣”，再调用 B 站官方接口拉黑该 UP，并立即写入当前浏览器的插件屏蔽名单；共享状态会被标记为待写入，下次打开插件时自动合并，不需要再点“同步B站拉黑名单”。若“不感兴趣”没有生效，后续拉黑不会执行；若不感兴趣成功但拉黑失败，按钮允许重试。

过滤和隐藏范围只限首页 `<main>` 推荐区域；顶部的消息、动态、收藏、历史和创作中心弹窗不会参与扫描或隐藏。

### Chrome 与 Edge 共用状态文件

共享文件名为 `bilibili-title-filter-state.json`，首次连接时会自动创建；公开发布的源码不包含作者的个人规则和屏蔽名单。在 Chrome 和 Edge 中分别打开插件，在“过滤规则”底部进入“共享文件设置”，选择同一个 `bilibili-title-filter` 文件夹。若页面显示“需要长期授权”，点击授权按钮，并在浏览器弹窗中选择“每次访问时允许”。首次连接会把该浏览器现有规则与文件内容取并集；之后修改标题、UP、分区、标签、特殊类型或屏蔽名单时会自动写回文件。另一浏览器打开插件或点击“立即更新”即可读取最新状态。

文件只包含过滤规则和统一屏蔽名单；屏蔽记录、质量缓存和近期推荐次数仍保存在各浏览器本机。取消连接不会删除共享状态文件。浏览器或扩展重装后，再次选择原文件夹即可恢复。

## 数据与权限

- `storage`：保存浏览器本机规则、屏蔽名单、共享文件授权记录和最近 100 条记录。
- `activeTab`：读取当前首页的屏蔽结果并执行“本次显示”。
- `www.bilibili.com`：在网页首页识别和过滤视频卡片。
- `api.bilibili.com`：读取官方拉黑名单和公开视频信息，并在用户点击首页“拉黑”且确认后执行官方拉黑；“内容不感兴趣”由当前卡片的 B 站原生菜单提交。

扩展通过当前卡片上 B 站自带的“不感兴趣”菜单完成反馈，不再读取页面内部推荐数据。

扩展只会在用户点击首页“拉黑”并确认后，向 B 站提交当前内容“不感兴趣”并修改官方拉黑名单；不会把数据发送到其他网站。

## 质量分说明

质量分以 60 分为基础。互动表现较低、同一 UP 在当前首页重复出现、近期多次推荐会扣分；投币、收藏和点赞表现较好会加分。视频时长不参与评分。互动比例加入了先验样本平滑，播放量很小的视频不会因为数据不足直接被隐藏。

- 宽松：低于 30 分隐藏。
- 标准：低于 42 分隐藏。
- 严格：低于 52 分隐藏。

视频公开数据会缓存在本机，避免每次刷新都重复请求。

## 已知限制

- 本项目是个人使用需求驱动的工具，与哔哩哔哩官方无隶属关系。当前面向 Chrome / Edge 桌面浏览器的网页首页。
- “质量分”是根据互动数据和重复推荐计算的经验指标，不代表视频内容的客观质量；可能误伤符合个人兴趣的视频，请按需要调整强度或临时恢复显示。
- B站页面结构、原生菜单和接口变化可能导致部分功能失效。遇到异常时可先关闭插件总开关，并记录浏览器版本、插件版本和复现步骤。
- 点击卡片上的“拉黑”并确认，会提交“不感兴趣”反馈并修改当前账号的官方拉黑名单；关闭插件总开关不会撤销这些账号操作。
- 共享文件采用合并规则与名单的方式，不是实时云同步。请勿将自己的共享状态文件或包含个人信息的截图提交到公开仓库。

## 开发与验证

本项目开发过程中大量使用了 AI 辅助生成与修改代码。功能取舍来自实际使用需求；AI 参与不代表代码已经过完整审计。

无需构建即可加载扩展。已安装 Node.js 时，可运行现有分组测试：

```sh
node tests/record-groups.test.cjs
```

运行 `node tests/serve-rendering-tests.cjs` 后，在浏览器打开输出的本地地址可查看渲染测试；同一地址下的 `/index.html` 是补加载测试。模拟页面测试不能替代真实 B站页面中的兼容性验证。
